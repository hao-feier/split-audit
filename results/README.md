# Result index — what each analysis answers

**Purpose.** Before asserting that an analysis is missing, check here. Several
"the authors never did X" claims were raised during review and refuted by files
that already existed; this table makes that lookup a single grep instead of a
guess.

Each row gives the **question the analysis answers**, not a file description.
An analysis that answers a question is *done*, even if the paper does not cite
it — citing is a writing decision, existence is a factual one.

`verify_manuscript_numbers.py` gate (o) asserts that every manuscript number has
a row here. Adding a number to the paper without a row fails the build.

## Rules for using this file

1. **"The authors never did X" requires a grep of this file first.** If a row
   exists, the claim is wrong. Three such claims were made and refuted during
   the 2026-10-15 review.
2. **Rows describe existence, not adequacy.** An analysis can exist and still be
   underpowered (E3-C) or rejected (e3b_composition_penalty_v0_INVALID.json is
   kept on purpose, under "superseded or invalid, retained as evidence").
3. **Two analyses that look alike are not interchangeable.** The fringe-removal
   cases above are the known trap; check the pixel distance before comparing
   their numbers.
4. **Superseded outputs stay on disk** with an explicit `_INVALID` suffix so a
   regenerated table cannot silently pick them up.
